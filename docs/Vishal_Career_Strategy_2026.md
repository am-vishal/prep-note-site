## 2. Three Career Paths

### Path A — Safest / Fastest: VTEX Specialist → Senior VTEX Developer / Tech Lead
- **Target titles**: Senior VTEX Developer, VTEX Technical Lead, E-commerce Engineer (VTEX)
- **Required skills**: Deep VTEX IO (you have this), leadership/mentoring signals, one integration story (ERP/OMS), basic system design articulation
- **Already have**: VTEX IO, React, Node, ERP integration experience, production deployment experience
- **Need**: Quantified achievements, one polished "led/owned" story, light system-design vocabulary
- **Difficulty**: Low — you're already 80% qualified
- **Time to interview-ready**: 6–8 weeks
- **Salary range**: ₹15–22 LPA at VTEX partner companies (Logixal-tier), ₹20–28 LPA if you land at a larger SI or a VTEX-using enterprise directly
- **Companies**: VTEX partners (Logixal, VML, Publicis Sapient, Newave, Ilha Solteira-type boutiques), D2C/retail brands running VTEX in-house
- **Why it fits**: Zero retraining risk — pure leverage of what you already do daily
- **Biggest risk**: VTEX-specific roles are a smaller market than generic React/Node roles — fewer openings at any given time, so job search takes longer even though prep is faster

### Path B — Highest Salary Potential: Full-Stack Engineer (React/Node) at Product Company or GCC
- **Target titles**: Senior Software Engineer, SDE-2, Full Stack Developer
- **Required skills**: React, Node (have both), SQL, cloud basics, DSA-level coding rounds, system design fundamentals
- **Already have**: React, Node, TypeScript, MongoDB, REST API integration
- **Need**: SQL (real gap), one cloud service, DSA practice (this is the real cost — product companies do coding rounds), system design basics
- **Difficulty**: Medium-high — DSA prep is the bottleneck, and at 30 min/day it's slow going
- **Time to interview-ready**: 7–9 months
- **Salary range**: ₹18–28 LPA realistic at mid-tier product companies/GCCs; ₹15–20 LPA safe floor
- **Companies**: GCCs (Walmart, Target, Myntra-adjacent), funded startups, SaaS companies
- **Why it fits**: Your core stack transfers directly; VTEX becomes a "bonus e-commerce domain knowledge" line rather than the headline
- **Biggest risk**: DSA/coding-round prep at 30 min/day genuinely takes the better part of a year to get interview-sharp — this path has the longest runway of the three

### Path C — Future-proof hybrid: VTEX/E-commerce Engineer with Cloud + AI-assisted engineering skills
- **Target titles**: Senior E-commerce Engineer, Digital Commerce Engineer, Composable Commerce Developer
- **Required skills**: Everything in Path A, plus cloud (AWS basics), plus comfort using AI coding tools (Copilot/Claude Code) to ship faster — increasingly explicitly asked about in 2026 JDs
- **Already have**: Path A's full skillset
- **Need**: AWS fundamentals (S3, Lambda, basic deployment), demonstrated use of AI-assisted development in your workflow story
- **Difficulty**: Low-medium — incremental on top of Path A, not a separate track
- **Time to interview-ready**: 3–4 months
- **Salary range**: ₹18–25 LPA, with the ceiling higher than Path A because "e-commerce + cloud + AI-fluent" is a genuinely rare combination in India right now
- **Companies**: Same as Path A, plus larger enterprise digital commerce teams (retail, D2C brands building composable commerce stacks)
- **Why it fits**: Extends your real strength (VTEX/e-commerce) rather than replacing it, adds just enough breadth to clear cloud-screening filters
- **Biggest risk**: Slightly smaller job pool than Path B, though larger than pure Path A since "e-commerce + cloud" roles are broader than pure VTEX roles

### Ranking: **C > A > B**

Path C wins because it keeps your fastest lever (VTEX depth) as the core while fixing your actual biggest resume weakness (no cloud) with the least new learning. Path A is the safe fallback if you want to move faster and accept a slightly narrower job pool. Path B is real but the DSA cost at 30 min/day makes it the slowest and highest-risk of the three for your timeline — don't choose B unless you specifically want to exit e-commerce entirely.

## 5–6. The 30-Minute Daily System + 12-Month Plan

### Daily ratio (customized to your profile — not the generic 10/10/10 split)
Since your biggest gaps are narrow (SQL, one cloud service) and your biggest lever is resume/positioning (not new technical breadth), your ratio shifts toward application/practice earlier than a typical plan:

- **15 min — learning/practical** (SQL, then AWS, then system design — sequential, not parallel)
- **10 min — hands-on** (apply that day's concept directly into your project upgrade from Section 8)
- **5 min — job-market activity** (resume line edit, one LinkedIn touch, or one saved job — rotates daily)

### Phase breakdown (12 months)

**Phase 1 — Foundation (Weeks 1–4): Resume triage + SQL basics**
- Mon: SQL — SELECT, JOIN, GROUP BY (use a free resource like Mode Analytics SQL tutorial or W3Schools SQL, no paid course needed)
- Tue: SQL — practice writing 2 queries against a sample dataset
- Wed: Resume — fill one row of the metrics checklist (Section 9) by actually checking with your project data/manager
- Thu: SQL — subqueries, basic indexing concept
- Fri: Resume — rewrite one bullet using Action+Tech+Problem+Scale+Result
- Sat: 30 min — reproduce 3 SQL queries from memory, no notes (retrieval practice)
- Sun: Rest

**Phase 2 — Skill upgrade (Weeks 5–10): AWS fundamentals**
- Mon: AWS — what EC2, S3, Lambda actually are (conceptual, via AWS's own free tier docs)
- Tue: AWS — deploy one static file to S3 (hands-on, free tier)
- Wed: Resume — continue metric collection + bullet rewrites
- Thu: AWS — basic IAM concept (permissions/roles — this comes up in interviews often)
- Fri: LinkedIn — write and publish your headline + About section (Section 10)
- Sat: 30 min — explain AWS S3 vs EC2 out loud, recorded, to check clarity
- Sun: Rest

**Phase 3 — Portfolio/project (Weeks 11–18): Build Project 1 from Section 8**
- Daily 30 min entirely on incremental project build (see Section 8 for exact breakdown) — no new learning topics introduced this phase, pure execution
- Sat: weekly review — what got built, what's blocking, adjust next week

**Phase 4 — Resume/LinkedIn finalize (Weeks 19–20)**
- Full resume rewrite using all collected metrics
- LinkedIn Featured section populated with Project 1
- Start light applications (Section 14) — don't wait for "done," start now

**Phase 5 — Interview preparation (Weeks 21–30)**
- Rotate: 2 days/week technical Q&A practice (use your existing VTEX prep + Section 11 bank), 2 days/week SQL/system-design practice, 1 day/week behavioral STAR story practice, Sat = mock interview or recorded self-answer review

**Phase 6 — Job applications (Weeks 20 onward, overlapping)**
- Ongoing from Phase 4 — 5–7 applications/week (Section 14), Sat networking touch (10–15 min)

**Phase 7 — Negotiation (as offers arrive, likely months 7–10)**
- Triggered by actual offers, not calendar — see Section 14 for approach

**Months 7–12 (condensed — themes repeat the Phase 5/6 system with rotating focus)**:
- Month 7–8: Build Project 2 (Section 8) in the daily slot, interviews continue in parallel using banked prep time from evenings/weekends if interviews are scheduled
- Month 9–10: Heavier interview cadence — reduce new learning to near-zero, pure interview practice + applications

## 8. Project Strategy

### Project 1: "Commerce Order Sync Dashboard" (build first, weeks 11–18)
- **Business problem**: Mirrors exactly what you already do professionally — visualizing/managing order sync status between an e-commerce platform and a downstream system (your JDE/Boomi experience, generalized).
- **Architecture**: React frontend, Node/Express backend, MongoDB for order records, one AWS S3 integration (file export), basic SQL-backed reporting layer if you add a Postgres read-replica for reporting (this single choice covers your SQL AND AWS gap in one project).
- **Technologies**: React, Node, Express, MongoDB, PostgreSQL (new, deliberately), AWS S3.
- **Features**: Order list with status (synced/failed/retry), manual retry trigger, CSV export to S3, simple dashboard chart of sync success rate.
- **Build**: Real CRUD, real retry-state-machine logic (this is your actual production knowledge, demonstrated).
- **Do NOT build**: Authentication from scratch (use a simple existing library), a custom UI design system, mobile responsiveness polish — none of these are what's being evaluated.
- **Effort**: ~25–30 hours total, fits the 8-week incremental window at 30 min/day.
- **Interview story**: "I built a project modeling the order-sync problem I handle professionally at [company] — it demonstrates retry/idempotency handling, which is the same pattern I use in production for our ERP integration."
- **Resume bullet**: *"Built an order-synchronization dashboard (React/Node/PostgreSQL) demonstrating idempotent retry handling for failed order pushes, modeled on production e-commerce-to-ERP integration patterns."*
- **README structure**: Problem → Architecture diagram → Setup → Key design decisions (idempotency, retry backoff) → Screenshots.

### Project 2: "VTEX-style Catalog API" (build months 7–8)
- **Business problem**: Demonstrates backend API design skill independent of VTEX itself — useful for Path B/C interviews where VTEX isn't known by the interviewer.
- **Architecture**: Node/Express REST API modeling Product → SKU → Specification hierarchy (exactly the structure you already know cold from VTEX), backed by MongoDB, with a PostgreSQL price/inventory service to demonstrate polyglot persistence reasoning.
- **Features**: Product CRUD, SKU variant handling, a simple "trade policy" style price-override endpoint (directly reusing your real VTEX knowledge as a generalized concept).
- **Do NOT build**: A frontend for this one — keep it API/backend-only, it's meant to demonstrate backend design depth.
- **Effort**: ~20 hours.
- **Interview story**: "I generalized the product/SKU/pricing model I work with in VTEX into a standalone API, partly to solidify my own understanding and partly to have something I could demo that isn't tied to a proprietary platform."
- **Resume bullet**: *"Designed and built a RESTful catalog API modeling product/SKU/pricing relationships, generalized from production e-commerce platform experience."*
